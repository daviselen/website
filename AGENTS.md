# Repository Guidelines

React 19 + Vite 8 + Tailwind 3 rebuild of the DE5 Figma file (`tnP43NMbcFkzFKMsdpukDn`). Figma is the source of truth; the code chases it. Routing is React Router 7, animation is GSAP (ScrollTrigger, ScrollSmoother, SplitText, MorphSVG via `@gsap/react`), and it deploys to Vercel (static build plus `./api` functions). CI uses Node 22.

## Project Structure & Module Organization

- `./src/main.jsx` — `createBrowserRouter` routes wrapped by `./src/components/Layout.jsx`: `/`, `/about`, `/about/retail-map`, `/careers`, `/contact`, `/work/social-media`, `/work/lakers-and-toyota-legendary-partners`, `/privacy-policy`, `/news/:slug`, `*`. Most pages are code-split (route `lazy` or `React.lazy`); Home and NotFound are in the main bundle. Layout owns the persistent chrome: `NavBarAlt`, `Footer`, the page-transition curtain, the preloader, and ScrollSmoother's `#smooth-wrapper > #smooth-content`.
- `./src/pages/` — one component per route. `./src/pages/news/` holds the article layouts; `richText.jsx` renders Contentful rich text.
- `./src/sections/` — one component per Figma section frame, each rendering a stable `id` (`#masthead`, `#proof`, `#portfolio-grid`, `#human-ai`, `#from-inside-out`, `#news-awards`, `#cta-banner`, `#footer`) that the visual tests select on. Renaming an id breaks `./tests/visual/design-diff.spec.js`. `NavBar.jsx` and `SocialPR.jsx` are unused legacy.
- `./src/design-system/components/` — components that exist because a Figma component (`Card`, `Button`, `DeLogo`, …) is used by more than one place. Check here before writing new markup. `./src/design-system/animation.js` is the one import point for gsap and its plugins, the shared motion tokens (`REVEAL_DURATION`, `EASE_REVEAL`, …) and `useSmoothScroll`.
- `./src/data/` — news articles as JSON (migrated from WordPress by `npm run migrate:wordpress`), `job-openings.json` (committed ADP snapshot). `./src/lib/` holds helpers, including `reducedMotion.js`.
- `./api/` — Vercel functions (`contact.js`, `locations.js`, `posthog.js`). Env vars are listed in `./.env.example`.
- `./vercel.json` sets the Content-Security-Policy. A new third-party script, image, fetch or iframe origin is blocked in production until it is added there.
- `./DESIGN.md` is the token reference; `./tailwind.config.js` is its implementation. The two are synced **by hand** — neither generates the other, so change both.
- `./src/index.css` holds the `@font-face` blocks. Knockout ships as separate family-named cuts (Featherwt/Bantamweight), not one family with a weight axis.
- `public/images/*.jpg` are the sources; the AVIF/WebP siblings are generated by `npm run images` (gitignored) and served by `Picture`.

## Responsive, Theme & Motion

- Figma frames are desktop, plus one mobile frame for Home: `HOME — / — MOBILE (iPhone 17 Pro, 402)`, node `3428:1051`. Anywhere there is no mobile frame, the responsive step-down is ours to design; reuse the site's existing ramps. `md` (768px) is where the nav goes inline and the phone layouts end.
- Phone type uses the fluid presets `text-fluid-sm … text-fluid-3xl` (anchored to the 402px frame, scaling 320–480px), then hands off to the existing `md:`/`lg:` classes. Desktop type uses `text-display-*`.
- The nav is one `<dialog>` element: a right drawer below `md`, the inline pill row from `md` (modelled on Bootstrap v6's navbar + drawer). Keep it a single element.
- Custom Tailwind variants/utilities: `light:` (`<html data-theme="light">`; dark is the base), `reduced-motion:` (`data-motion`), `scrollbar-none`. In JS, always use `prefersReducedMotion()` from `./src/lib/reducedMotion.js` so the Motion toggle and the OS setting agree.
- ScrollSmoother: anything `position: fixed` must live outside `#smooth-content`; it is off under reduced motion; `normalizeScroll` is configured with `allowNestedScroll`, so nested scrollers work. A modal that locks scroll should also call `ScrollSmoother.get()?.paused(true)`.

## Build, Test, and Development Commands

```bash
npm run dev                       # vite dev server on :5173 (predev: npm run images)
npm run build                     # production build (CI gate); prebuild runs images + jobs
npm run jobs                      # refresh src/data/job-openings.json from ADP + PWA assets
npm run lint                      # eslint .; lint:fix to autofix
npm run test:visual               # playwright; auto-boots dev server
npm run test:visual -- design-diff # pixel diff vs committed Figma exports
npx playwright test -g masthead   # single section
npm run test:visual:report        # open last HTML report
```

`npm run jobs` keeps the committed snapshot if ADP is unreachable. Tailwind config changes are not picked up by a running dev server — restart it.

## Coding Style & Naming Conventions

`./.prettierrc.json`: double quotes, semicolons, trailing commas, 80 cols, 2-space indent. Prettier is not enforced in CI and existing files are not uniformly formatted, so match the file you are editing. ESLint flat config layers react, react-hooks, jsx-a11y, and tailwindcss; `react/prop-types` is off (plain JS, no PropTypes anywhere).

`tailwindcss/no-arbitrary-value` and `no-custom-classname` are **errors**. The file lists in `./eslint.config.js` downgrade them to warn for pre-existing files only — new files get no exemption. Name tokens after real Figma variables (`surface.alt`, `spacing["400"]` ↔ `Scale/400`), never hex or raw px. A token that is not a Figma variable (the fluid type presets, the extra aspect ratios) carries a `Not a Figma token` comment in the config.

## Testing Guidelines

`./tests/visual/design-diff.spec.js` diffs each section against a committed `./tests/visual/design/<name>.png` export via pixelmatch. Exports must be @1x at 1792px, cropped to exact frame bounds (see `./tests/visual/design/README.md`); >24px size drift fails as misconfiguration. It is desktop-only (1856px viewport).

It is no longer a gate. CI (`./.github/workflows/visual.yml`) runs it on pull requests as information only — it passes unless the crop sizes mismatch — and the exports for sections that already exist are stale. Do not update exports or flag diffs after UI changes to existing sections; it is still reasonable for brand-new pages. The CI check that matters is `npm run build` (`./.github/workflows/ci.yml`).

## Figma Pulls

Run `/figma-pull` (`./.claude/skills/figma-pull/SKILL.md` → `./.claude/workflows/figma-pull.js`). Manual fallback and the rationale for each rule live in `./FIGMA_WORKFLOW.md`: use `get_design_context` over raw REST JSON, always call `get_variable_defs`, and close every pull with a `get_screenshot` side-by-side. Figma text frames use cap-trimmed text boxes, so compare image sizes and gaps rather than text box heights.

## Commit & Pull Request Guidelines

Short imperative subjects, sentence case, no prefix or scope: `Build About page`, `Fix image card expansion bug`. No PR template; CI runs build on every PR and uploads visual diff artifacts.
